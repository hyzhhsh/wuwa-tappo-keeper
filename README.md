# Wuwa Tappo Keeper

Wuwa Tappo 无人值守工具，通过 HTTP 和 WebSocket 与 Wuwa Tappo 服务交互的 Python 命令行工具。完成首次登录后，可持续上报点击、自动开启宝箱，并通过飞书机器人接收开箱结果。

## 功能

- **自动上报点击**：默认每次随机增加 20–60 次点击，上报完成后间隔 30–32 秒再进行下一次上报。
- **自动开箱**：同步服务器时间，检查左右宝箱的就绪状态；可用点击数达到 1000 且宝箱就绪时自动开启，优先左箱。
- **自动续期**：定期检查 Token 有效期，剩余不足 48 小时时尝试续期，并保存本地凭据。
- **断线重连**：维护 WebSocket 心跳，断线后自动重连；上报失败时保留有限的点击缓冲。
- **飞书通知**：可选发送开箱卡片，展示奖励、稀有度、点击消耗、剩余点击和下一宝箱状态，并提供可用的奖励原图链接。
- **运行控制**：支持试运行、限定上报周期、仅上报不开箱和调试日志。

无人值守运行依赖有效的登录凭据。首次登录需要人工输入验证码；后台凭据失效时程序会退出，需要在交互终端重新登录后再启动。

## 安装与快速开始

建议使用 **Python 3.10 或更新版本**。运行环境需要能够连接 Wuwa Tappo 服务；手机号登录还需要连接库洛 SDK 服务，飞书通知需要连接对应
webhook。

下载项目后，在项目根目录执行以下命令。Python 依赖为 `requests` 和 `websocket-client`
，版本范围见 [requirements.txt](requirements.txt)。

### Windows（PowerShell）

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 首次交互登录，并按提示设置可选的飞书 webhook
.\.venv\Scripts\python.exe wuwa_tappo.py --login

# 登录完成后，启动持续运行
.\.venv\Scripts\python.exe wuwa_tappo.py
```

以上命令直接使用虚拟环境中的 Python，无需激活虚拟环境。若本机使用 `py` 启动器，可将创建虚拟环境的命令改为
`py -3 -m venv .venv`。

### Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

# 首次交互登录，并按提示设置可选的飞书 webhook
.venv/bin/python wuwa_tappo.py --login

# 登录完成后，启动持续运行
.venv/bin/python wuwa_tappo.py
```

若创建虚拟环境时提示缺少 `venv`，请先通过系统包管理器安装对应 Python 版本的 venv 支持。

启动后，控制台会输出账号、累计点击、可用点击、Token 剩余有效期及左右宝箱状态。前台运行时按 `Ctrl+C` 停止，程序会尝试补报缓冲点击并保存凭据。

## 登录方式

执行 `--login` 会强制进入登录流程，并在完成登录、保存凭据后退出；需要再次执行启动命令才能持续运行。不指定登录方式时，会显示交互选择菜单。

下文使用 `python` 简写解释器命令，请替换为上述系统对应的虚拟环境 Python 路径。

### UID + 游戏内站内信验证码

```bash
python wuwa_tappo.py --login --login-method uid
```

按提示输入 9–10 位游戏 UID，再输入游戏内站内信收到的 6 位验证码。若自动发码失败，程序仍允许输入从官方客户端或游戏内站内信获取的验证码。

### 库洛通行证手机号 + 短信验证码

```bash
python wuwa_tappo.py --login --login-method phone
```

当前手机号流程支持中国大陆 11 位手机号，可带 `+86` 前缀；输入短信验证码后查询鸣潮角色。短信验证码通常为 4 位，程序接受 4–6
位数字。若查询到多个角色，当前实现自动使用第一个角色，不提供角色选择菜单。

手机号与验证码不会写入凭据文件；程序会保存随机设备号以便复用。手机号登录流程按国内角色查询，其他地区账号的兼容性尚未验证。

如果发送短信需要滑块验证，可在官方客户端申请验证码，再回到终端输入；若提交验证码或换取 Token 时仍要求滑块验证，程序无法自动完成，需要改用
UID 登录，或先在官方客户端处理登录问题。

## 运行方式与命令行参数

```bash
# 持续上报并自动开箱
python wuwa_tappo.py

# 只执行一个试运行周期，不上报点击、不开箱、不发送开箱通知
python wuwa_tappo.py --once --dry-run

# 运行 10 个上报周期后退出
python wuwa_tappo.py --cycles 10

# 持续上报点击，但不开宝箱
python wuwa_tappo.py --no-open

# 正常运行并输出调试日志
python wuwa_tappo.py --debug

# 查看帮助
python wuwa_tappo.py --help
```

| 参数                           | 作用                                 |
|------------------------------|------------------------------------|
| `-h`、`--help`                | 显示帮助后退出。                           |
| `--login`                    | 强制重新登录、设置飞书 webhook，完成后退出。         |
| `--login-method {uid,phone}` | 指定需要登录时采用的方式；已有有效凭据时不会仅因该参数重新登录。   |
| `--once`                     | 运行一个上报周期后退出；同时指定 `--cycles` 时以此为准。 |
| `--cycles N`                 | 运行 N 个上报周期后退出，默认 `0` 表示持续运行。       |
| `--dry-run`                  | 模拟点击上报与开箱判断，不实际提交点击、开箱或发送开箱卡片。     |
| `--no-open`                  | 正常上报点击，但不开宝箱。                      |
| `--test-webhook`             | 使用本地凭据中的 webhook 发送一张飞书测试卡片后退出。    |
| `--debug`                    | 输出协议调试日志，包括心跳和服务端事件。               |

`--dry-run` 仍需有效凭据，会联网校验账号、同步状态和建立 WebSocket 连接，也可能续期 Token、保存凭据；请先完成登录。
`--test-webhook` 是独立的发送测试入口，即使同时传入 `--dry-run` 也会发送测试卡片。

`--once` 和 `--cycles` 限制的是上报周期数，不保证每个周期都被服务端成功接受。有限周期运行时，若连续 5
次因连接或初始状态问题跳过上报，程序会以失败状态退出。

## Linux 后台运行

先在交互终端完成登录，确认前台能够正常运行并停止前台进程，再从项目根目录使用以下命令启动后台进程：

```bash
nohup .venv/bin/python wuwa_tappo.py >>tappokeeper.log 2>&1 &
```

查看日志与运行进程：

```bash
tail -f tappokeeper.log
pgrep -af '[w]uwa_tappo.py'
```

核对进程列表中的命令和 PID，确认属于本项目后，将下方 `12345` 替换为实际 PID，发送 SIGTERM 正常停止：

```bash
kill -TERM 12345
```

程序收到 SIGTERM 后会尝试补报缓冲点击、关闭连接并保存凭据。使用 `tail -f` 时，`Ctrl+C` 只停止日志查看。

上述命令仅负责将进程放到后台，不提供开机启动、进程守护、自动重启或日志轮转。重复执行会启动多个进程；同一账号应只保留一个运行实例，避免与其他实例或官方客户端争用连接。后台启动后应检查日志，确认登录校验和连接成功。

## 飞书开箱通知

1. 在飞书群中添加自定义机器人，复制其 webhook URL。
2. 执行 `python wuwa_tappo.py --login`，登录成功后按提示粘贴 webhook；直接回车表示关闭通知。
3. 执行以下命令发送测试卡片：

   ```bash
   python wuwa_tappo.py --test-webhook
   ```

测试命令会真实发送消息，发送失败时返回非零退出状态。正常运行时，开箱成功后异步发送通知；通知失败只记录日志，不中断主流程，也不提供持久化重试队列。

当前仅使用 webhook URL 发送卡片，未实现飞书机器人的签名校验参数。如果机器人启用了签名校验，该配置无法直接使用；若使用关键词或
IP 白名单规则，也需确保它们允许实际卡片内容和运行主机。默认通知标题为 `Wuwa Tappo · 开箱成功`。

可在停止程序后修改凭据文件中的 `feishu_webhook` 字段，更换 URL 或设为 `""` 关闭通知，随后重新启动；也可重新执行 `--login`
设置。

## 配置与凭据

### 常用源码配置

运行参数集中在 [wuwa_tappo.py](wuwa_tappo.py) 顶部的常量中，修改后需重启程序。

| 常量                                      | 默认值                 | 说明                                   |
|-----------------------------------------|---------------------|--------------------------------------|
| `REPORT_CLICK_MIN` / `REPORT_CLICK_MAX` | `20` / `60`         | 每周期随机增加的点击数，需满足 `1 ≤ MIN ≤ MAX`。     |
| `REPORT_INTERVAL_SEC`                   | `30` 秒              | 上报后的基准间隔，另随机增加 0–2 秒；请求耗时等可能使实际周期更长。 |
| `CHEST_CHECK_INTERVAL_SEC`              | `30` 秒              | 定时刷新账号与检查宝箱的间隔，上报成功等情况也会触发刷新。        |
| `CHEST_CLICK_COST`                      | `1000`              | 自动开箱所需的可用点击门槛，实际扣除以服务端响应为准。          |
| `OPEN_DELAY_SEC`                        | `3` 秒               | 连续开启左右宝箱之间的等待时间。                     |
| `MAX_PENDING_CLICKS`                    | `200`               | 待上报点击缓冲上限，超出部分丢弃。                    |
| `SERVER_TIME_SYNC_SEC`                  | `300` 秒             | 服务器时间同步间隔；首次同步成功前暂停自动开箱并更频繁重试。       |
| `RENEW_CHECK_SEC`                       | `600` 秒             | 运行期间 Token 有效期检查间隔。                  |
| `RENEW_THRESHOLD_SEC`                   | `48 * 3600` 秒       | Token 剩余有效期低于 48 小时时尝试续期。            |
| `WEBHOOK_TITLE`                         | `Wuwa Tappo · 开箱成功` | 飞书开箱卡片标题。                            |

### 本地凭据

`credentials.json` 在登录后自动生成于脚本同目录，与启动时的工作目录无关。文件保存 Token、过期时间、账号标识、昵称、登录方式、飞书
webhook，以及手机号登录使用的设备号等信息；无需手工编写。

后台凭据失效时，先确认旧进程已经退出，再在交互终端重新登录，完成后重新启动。程序日志输出到控制台，文件记录由重定向或启动脚本完成。

## 常见问题

| 现象                                 | 处理方式                                                                  |
|------------------------------------|-----------------------------------------------------------------------|
| 后台提示“登录需要交互式终端”                    | 先在终端执行 `--login`，完成验证码输入并保存凭据，再后台启动。                                  |
| UID 验证码错误或请求频繁（`10031`）            | 检查 UID 与最新的 6 位验证码；发码限流通常需等待约 15 分钟，以服务端实际行为为准。                       |
| UID 发码或登录被拒绝（`10007` / HTTP `403`） | 发码失败时可尝试输入官方渠道取得的验证码；登录仍被拒绝时尝试使用手机号登录。                                |
| 手机号流程要求滑块验证                        | 发码阶段可通过官方客户端申请验证码后回填；提交验证码或换取 Token 阶段需要滑块时，尝试改用 UID 登录。              |
| 库洛 SDK 返回 `code 10`                | 这是通用拒绝，可能涉及请求参数或风控；保留错误中的 `request_id` 便于排查。                          |
| 点击上报被限流（`80013`）                   | 程序保留点击缓冲，等待后续周期重试；检查是否修改了上报间隔或存在重复实例。                                 |
| 点击数被判定异常（`70003`）                  | 程序会清空缓冲、刷新账号状态，并暂停上报 5 分钟；检查重复实例及点击配置。                                |
| 登录凭据失效（认证错误 `10003` / `90002`）     | 前台可进入重新登录；无交互终端的后台运行会退出，需手动执行 `--login` 后再启动。                         |
| 宝箱没有自动开启                           | 检查是否启用了 `--no-open` 或 `--dry-run`、服务器时间是否同步成功、宝箱是否就绪，以及可用点击是否达到 1000。 |
| 飞书没有收到通知                           | 先执行 `--test-webhook`，检查 webhook、机器人安全设置和日志；普通运行仅在开箱成功后发送开箱通知。         |

排查连接和协议问题时可使用 `--debug`。分享日志前检查账号标识、奖励等内容，并移除个人信息；无需提供 `credentials.json`。
